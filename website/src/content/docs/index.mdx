## Why mikro-orm-markdown

<CardGrid>
  <Card title="ERD + column tables" icon="document">
    A Mermaid ER diagram plus per-entity tables with real DB column names, keys, nullability,
    descriptions, indexes, and constraints.
  </Card>
  <Card title="Driven by JSDoc" icon="pencil">
    Descriptions, sections (`@namespace`, `@erd`, `@describe`), and visibility (`@hidden`) come
    from the comments already in your entity files.
  </Card>
  <Card title="MikroORM-aware" icon="puzzle">
    Embeddables, single table inheritance, `@Formula`, and `EntitySchema` / `defineEntity()`
    entities render as first-class concepts.
  </Card>
  <Card title="No database needed" icon="rocket">
    Reads entity metadata through MikroORM discovery. Works with MikroORM 6 and 7 on SQLite,
    PostgreSQL, MySQL, and MariaDB drivers.
  </Card>
</CardGrid>

## From entity to diagram

<div class="input-output">
<Code
  title="post.entity.ts"
  lang="ts"
  code={`/**
 * Blog post authored by a registered user.
 * @namespace Blog
 */
@Entity()
export class Post {
  @PrimaryKey({ type: 'integer' })
  id!: number;

  /** Post title */
  @Property({ type: 'string' })
  title!: string;

  @Property({ type: 'text', nullable: true })
  body?: string;

  @ManyToOne({ entity: () => Author })
  author!: Author;
}`}
/>

  }
  Post }o--|| Author : "author"`}
/>
</div>
